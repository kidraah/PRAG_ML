# The Gradient: how PRAG trains its personas

PRAG's first half collects what Instagram's algorithm feeds a persona. The Gradient is the second half: models
that learn from that feed and nothing else, so you can measure what each persona was shaped by, talk to it, and
make two personas argue.

The short answer to "are we tuning an open LLM or building a new model?": **both kinds of model are trained, and
neither is built from scratch.**

| Model | What it is | What it learns | What it's for |
|---|---|---|---|
| **Preference model** (one per persona) | A classifier: text features → logistic regression | Will this persona watch a reel to the end and engage? | The measurable ML result; ranks evidence for chat; the feed predictor |
| **Whose-feed model** (shared) | The same kind of classifier | Which account's feed a reel came from | Shows how far apart the two feeds are; the feed predictor |
| **Persona language model** (one per persona) | A LoRA adapter on a frozen open LLM (Qwen3 4B Instruct, 4-bit, on MLX) | To talk as this persona, about what its feed showed it, citing it | Chat, debate, one question two worldviews |

Measured results for the latest versions are in [results/gradient.md](results/gradient.md), regenerated by
`python -m gradient.report` after every retraining.

## The data

```
                                     ┌─────────────────────────────┐
 Instagram sessions (reels.db) ──┐   │      the training corpus     │
 Reels written for each feed  ───┼──▶│  items: one per unique text  │──▶ splits fixed per story group
 News headlines (RSS)         ───┤   │  feed:  what each persona saw│
 Wikipedia articles           ───┘   │  labels: Jev, per persona    │
                                     │  takes: the persona's words  │
                                     └─────────────────────────────┘
```

- **Items** are unique pieces of content, deduplicated by their text. Each one records where it came from:
  an Instagram session, a reel written for a feed by an LLM (Qwen 3.5) following that persona's profile, an RSS
  headline, or Wikipedia.
- **The latest news.** `python -m gradient.news` pulls the newest stories from the outlets' own RSS feeds (The Hindu,
  The Indian Express, Mint, NDTV, Hindustan Times, The Times of India, BBC), keeps each as an item linked to its
  article, and lets each persona's preference model pick the stories its feed would serve. Reels are then written
  about those real stories, told to add no facts beyond the headline and summary, so the feeds stay current rather
  than timeless.
- **The feed** of each persona is the part of the corpus it has seen. That covers the reels its sessions recorded,
  the reels written for its feed, and the headlines the recommender served it, which are drawn by the persona's
  own Jev score. It is the persona's only source of knowledge: chat and debate retrieve from it and nothing else.
- **Labels.** Jev (TypeSafe) judges every item for both personas: would this person watch it to the end and
  engage? Every item is judged, not only the ones in the feed, because a feed alone has almost no negatives to
  learn from. The binary label is a Jev score of 0.5 or more. The graded score is stored separately and is never
  used as a feature.
- **Takes** are each persona's reaction to a reel in its feed, in its own words. The persona language model
  learns its voice from these.
- **Splits** are assigned once per group. A group is a story's retellings, or the eight reels written from one
  brief, so near-duplicates never end up on both sides of train and test. Each persona's first training run
  freezes its test items as the evaluation set, and every later version is scored on exactly the same items.

**Persona profiles.** @mlproject01 is a right-leaning civil engineer in Indore. Their interests are national
security, infrastructure and government schemes, plus cricket, gadgets, Hindi comedy and street food.
@mlproject02 is a left-leaning teacher and union member in Pune. Their interests are labour, public services,
civil liberties and the environment, plus football, indie music, photography and gaming. Both share science and
technology. Their structured profiles (topic weights, stance and language preferences) are in
`biases/<account>.json` and editable in the panel.

## 1. The preference model: supervised classification

**Task.** Binary classification of reel text. The target is "this persona engages" (Jev's label). The target is
not whether the content is true, and not the persona's politics.

**Candidates, all on the same splits:**

1. **Majority class.** The floor: always predict the commoner answer.
2. **Quick rules.** The persona's own watch words and skip words. This is the hand-written heuristic the
   sessions already use, and the baseline a learned model has to beat.
3. **TF-IDF + logistic regression.** Word 1–2 grams plus character 2–5 grams. Character n-grams cope with
   Hinglish spelling ("nahi", "nahin", "nai") and with Devanagari without a tokenizer.
4. **Multilingual sentence embeddings + logistic regression.** `paraphrase-multilingual-MiniLM-L12-v2` maps Hindi,
   Hinglish and English text with the same meaning to nearby vectors.

Regularisation strength (C) and the decision threshold are picked on **validation**. The model with the higher
validation PR-AUC is kept. The **test** split is only ever scored. The metrics reported are precision, recall,
F1, PR-AUC, ROC-AUC, precision@50, the Brier score and the confusion matrix, broken down by source and by
language.

**Leakage control.** Features read only the reel's text. Creator handles and the persona's city (the writer often
mentioned Pune or Indore) are scrubbed out, otherwise the model learns "mentions Pune" instead of the content.
Persona IDs, teacher scores and provenance never reach the features.

**Why these models, and not others:**

- *Not a fine-tuned transformer classifier (e.g. BERT).* With about 20,000 short texts, linear models over good
  features are within a few points of a fine-tuned encoder. They train in seconds, so retraining on every new
  batch is cheap, and they're interpretable: the Training tab shows the words each persona's model leans on.
- *Not gradient-boosted trees.* They are no better than linear models on sparse TF-IDF text features, and harder
  to read.
- *Logistic regression's probabilities are calibrated enough* to blend into retrieval and to threshold. The Brier
  score is reported to check this.

## 2. The persona language model: parameter-efficient fine-tuning (LoRA)

**What's trained.** The base model (Qwen3 4B Instruct, 4-bit quantised) is **frozen**. For each persona a LoRA
adapter is trained: pairs of small low-rank matrices (rank 16) added to 16 of its layers. That's under 1% of the
weights, a file of a few tens of MB per persona. Training is supervised fine-tuning on chat examples, with the
loss masked to the reply only. The examples are built from that persona's feed and nothing else:

| Example | Input | Target |
|---|---|---|
| Reaction | "This reel just came up: …" | The persona's take on it |
| Grounded answer | A question, with 3–4 reels from the feed on one story or topic, numbered as evidence | The persona's answer, 3–5 sentences that interpret the reels and cite each claim, e.g. "[2]" |
| Abstain | A question the given reels don't cover | "My feed hasn't shown me anything about that" |
| Debate | "The other side said: …" (the other persona's real take on the same topic), with reels as evidence | This persona's answer to it, citing its own reels |

**Where the answers come from.** The grounded and debate answers are written by an LLM (`gradient/answers.py`,
about 3,000 per persona): it gets the persona and the reels, and writes the question a friend might ask and the
answer in the persona's voice. It's told to say what the reels report in its own words, cite every claim, and never
paste a caption. The first adapters (v1, v2) learned from template answers that pasted captions, and that's what they
did in chat. lora-v3 is trained from the base model on the written answers instead.

**Evaluation.** Perplexity on held-out examples (from test-split reels the adapter never trained on), measured
three ways: the base model, the base model plus this persona's adapter, and this adapter on the *other* persona's
held-out examples. The adapter should beat the base model on its own persona and fit the other persona worse.
That shows it learned this persona, not just the answer format.

**At answer time** (chat, debate, compare), retrieval-augmented generation:

```
question ──▶ embed ──▶ search this persona's feed only ──▶ rank: similarity + 0.15 × p(persona engages)
                                                                │        (the preference model)
                                                                ▼
                         persona LoRA model  ◀── top reels, numbered, as evidence
                                │
                                ▼
                  answer ──▶ citations checked against what was retrieved (invalid ones removed)
```

**Why this approach, and not the alternatives:**

- *Not a new model trained from scratch.* A language model that can hold a conversation needs billions of
  tokens of text. A persona's feed is a few hundred thousand. A model trained only on that would produce
  reel-shaped babble, not answers. So "the dataset is its only source of information" is achieved differently:
  the base model supplies language, and the feed supplies everything the persona knows *about the world*.
  Retrieval is restricted to the feed, and the adapter is trained on it and taught to refuse beyond it.
- *Not full fine-tuning.* Updating all 4B weights per persona needs far more memory than a 24 GB Mac has, and
  produces an 8 GB copy per persona. LoRA trains on this Mac in minutes, stores a small file per persona, and
  leaves the base model untouched, so both personas share it.
- *Not prompting alone* (a system prompt describing the persona). That gives a caricature of what you write in
  the prompt. The adapter learns from the persona's actual reactions to thousands of reels, and its effect is
  measurable as the perplexity gap.
- *Not retrieval alone.* Retrieval supplies facts, but the voice, the framing, and what the persona notices and
  dismisses come from training.
- *Why a 4B model:* it's the largest that trains with LoRA comfortably in 24 GB of unified memory while
  generating at conversational speed. Qwen3 handles Hindi and Hinglish.

## 3. Training again and again as the data grows

The corpus is append-only and every ingestion is a numbered batch, so retraining is a single command:

```bash
python -m gradient update          # new session reels in → Jev labels → takes → retrain both preference models
python -m gradient update --lora   # …and continue each persona's LoRA adapter
```

(or the panel's Training tab). What happens:

- **Preference models are retrained** on the whole accumulated corpus, which takes seconds. Each run is a new
  version (`models/gradient/<account>/preference-vN.joblib`), and every version is scored on the persona's frozen
  evaluation set, so v1 → v2 → v3 is a fair comparison. Old versions are kept. This is periodic retraining, not
  online learning. It is the simplest correct choice while a full retrain is this cheap.
- **LoRA adapters are continued, not restarted.** A new version starts from the previous adapter and trains on
  the new batches' examples plus a replay sample of the old (30%). The replay guards against forgetting what
  earlier batches taught. Each version is a new folder (`lora-vN`), and the panel uses the newest unless an
  older one is made active.
- **What continuing measured, honestly.** lora-v2 (300 steps on the latest-news reels, session reels and debate
  examples, plus a 30% replay of the old) learned to debate and to talk about this week's stories, but on v1's
  held-out examples its perplexity rose: @mlproject01 from 3.85 to 4.27, @mlproject02 from 3.34 to 4.34. Both are
  still far below the base model's 80 and 131, and still lower on their own persona than on the other's. That's
  partial forgetting. The next version should replay more of the old data, or train new and old together.
- **lora-v4 (25 October), and why chat still uses v3.** v4 continued v3 on the reels the appended simulated
  sessions served each persona: about 840 new examples per persona (written answers built around those reels,
  takes, abstentions) plus a 30% replay of the old, 500 steps for @mlproject01 and 300 for @mlproject02. On v1's
  held-out examples, which every version is scored on:

  | Adapter | @mlproject01 | @mlproject02 |
  |---|---|---|
  | base model | 80.5 | 130.6 |
  | lora-v1 | 3.85 | 3.34 |
  | lora-v2 | 4.27 | 4.34 |
  | lora-v3 | **5.14** | **5.20** |
  | lora-v4 | 6.57 | 5.75 |

  (v1 and v2 score best here because these examples are in their template style, which v3 was trained away from.)
  On v3's own written-answer test set, @mlproject01's v4 also scored worse (5.85 against v3's 4.92; its step-200
  checkpoint 5.50). Validation loss rose while training loss kept falling, most steeply in the second pass over the
  data: v4 forgot more than it gained. So v3 stays active for both personas (`python -m gradient.lora --account
  NAME --activate 3`; `--activate 0` goes back to the newest). v4 is kept and shown on the Training tab, and a
  future continuation starts from the active adapter. A comparison on the new reels' own held-out examples was
  started but stopped when the Mac ran low on memory, so whether v4 is better on those reels is untested.
- **After every Instagram session**, `daily.py` adds the session's reels to the corpus and has Jev label them.
  Retraining stays a deliberate step.
- **If a persona's text changes,** its fingerprint changes, its items are judged again under the new persona, and
  the next model version trains only on labels for the persona as it is now.

## 4. What it can and can't claim

- The preference model predicts **Jev's** judgement of the persona. Agreement with Jev is not evidence of
  predicting a real person. The blind head-to-head (Label tab) compares Jev with a human labeller on real reels.
- Reels written for a feed by an LLM follow the persona's profile and the way a curated feed leans. They're
  realistic text, not real Instagram posts, and the corpus records that for every item. The by-source rows in the
  results show how the models do on real Instagram reels against the rest.
- The personas are fictional individuals, not stand-ins for everyone who shares their politics.
- lora-v1 and v2 learned from template answers and pasted captions back. lora-v3 learns from written answers and
  interprets instead; its Hinglish can still be clumsy, which is the ceiling of a 4B model.
- Citation checks and abstention training make answers better grounded. They can't guarantee a model never says
  something unsupported. And a persona believing something doesn't make it true: that's what the "Real or not"
  phase is for.

## Simulated sessions

`python -m gradient.simulate` builds 14 days of **simulated** sessions for both personas in their own database
(`datasets/demo-sessions/reels.db`). The panel shows them only when Data is set to **Simulated**, under a
"Simulated sessions" banner on every tab; Live shows the real sessions and nothing else. It refuses to replace an
existing simulation unless given `--fresh`.

`python -m gradient.simulate --append` adds sessions on the same days around the existing ones and changes none of
them. The current database is the first simulation (84 sessions, 3,441 impressions, three a day) plus one appended
batch (140 sessions, 13,719 impressions, five a day at other times of day): 17,160 impressions, 15,883 of them not
ads. The recommender carries on from what the existing sessions taught it, replayed in time order; a reel the
existing sessions served is never served again. Each appended session records its batch and its own generation
time. Feeds and reports order sessions by when they started, not by id, so the appended sessions sit in their days.

- **The recommender.** It serves the corpus's written reels, with news reels only from the day their story was
  published. It never sees the persona's scores: it learns topic and stance affinities from what the persona watches,
  likes and skips. A cold-start prior favours mass-appeal content on day one and fades, so the feed narrows the way a
  real one does: the share of reels that fit the persona rises from about 70% on the first day to about 90% on the
  last.
- **The persona.** The score is Jev's judgement for the persona, and the session's own engagement policy
  (`agent/bandit.py`) turns it into skip / watch / full watch / rewatch, dwell time, likes, saves and follows.
- **What's recorded.** Sessions and impressions in the live schema, so the Run, Feed, Digest and Report tabs work
  unchanged. Each session has its console log, timestamped in simulated time (Run tab: pick a day and a session,
  read the log or replay it). It also stores its simulated start and end, and when it was really generated.
- **Digests.** Built for each simulated day by the digest's own code; a reel about a real story cites that article.
- **Training.** The simulation draws on the training corpus, and the reels it served from outside a persona's feed
  join that feed (`via = demo_session`), so chat and debate know what the simulated feed showed them.

## Commands

```bash
python -m gradient.generate --account mlproject01 --reels 6000   # write reels for a feed (resumable)
python -m gradient.news --days 14 --search --stories 1000        # reels about the last two weeks' real news
python -m gradient.answers --account mlproject01 --n 3000        # written answers for the persona language model
python -m gradient.simulate                                      # 14 days of simulated sessions (--fresh replaces)
python -m gradient.simulate --append                             # more sessions on the same days, existing kept
python -m gradient build              # first time: earlier corpus + sessions + labels + headlines + models
python -m gradient update [--lora]    # every time after: new data → labels → retrain
python -m gradient.lora --account mlproject01 [--resume]         # train / continue one adapter
python -m gradient.lora --account mlproject01 --activate 3       # the adapter chat and debate use (0: newest)
python -m gradient status             # what's in the corpus
python -m gradient.report             # write docs/results/gradient.md
python -m gradient chat --account mlproject02 "What's going on with air pollution?"
python -m gradient debate --topic "The Agniveer scheme"
python -m gradient compare "Is the government handling unemployment well?"
python launch.py                      # the panel: Corpus, Training and Ask tabs
```
